Open Files from the dock, with Super+E, or by double-clicking a folder. From a terminal: aurora-files [FOLDER or LOCATION].

Sidebar
Home, Desktop, Documents, Downloads, Music, Pictures, Videos, Trash, plugged-in drives (click to mount, ⏏ to eject), Computer (/), Network and Connect to Server…. When a file or folder is “in use” and can't be moved, deleted or ejected: lists the programs of yours that have it (or anything in the folder) open, with End Task for each and End All.

Cut, Copy, Duplicate, Rename…

For several files: replace a piece of text in all their names at once. No file is ever overwritten.

For two folders: what is only in one, and what differs.
SHA-256 Checksums
Computes them in the background, to check a download.
Move to Trash, Properties
Properties shows size, type, dates, location and permissions.

On empty space: New Folder…, New File… (from templates in ~/Templates), Paste, Select All, Open in Terminal, Properties.

Undo and Redo (Ctrl+Z, Ctrl+Shift+Z) work for moves, renames, copies and moving to the Trash.

Trash

Items moved to the Trash can be restored to where they were (Restore) or deleted for good (Delete Permanently, or Shift+Delete without the Trash). Empty Trash deletes everything in it. Storage Sense can empty old items by itself (Storage).

Network folders

Network in the sidebar lists computers and NAS boxes that share folders on your network that announce themselves (most NAS boxes, Macs and Linux computers do). Recent Windows versions don't: open them with Connect to Server… and their address. Connect to Server… opens any address:

When a password is needed, Files asks, and can remember it in your keyring. Connected servers appear in the sidebar with ⏏ to disconnect.

Keyboard shortcuts in Files

Open it with Ctrl+Shift+Esc, from the Aurora menu, from Launchpad, or with aurora-taskmanager.

Processes

Three groups, each with CPU (a share of the whole computer, as on Windows), memory and disk activity:

Apps
Everything that has a window. An app's processes (for example a browser's many content processes) are folded under it with their count; double-click or right-click → Expand to see them.
Background processes
Your other processes: the shell, the compositor, sound, sync clients…
System processes
Other users' and the system's, when Show system processes is ticked.

Click a column's title to sort by it. Busy values are highlighted.

End Task (Delete)
Asks the app to quit, like closing it.
Kill (Shift+Delete)
Stops it at once, without saving.
Open File Location
Shows the program's file in Files.

System processes can only be stopped by the administrator; use sudo kill PID in a terminal.

Performance

The last minute as graphs in your accent color:

  • Processor: use, cores, average speed, up time.
  • Memory: in use and total, available, cached, swap in use.
  • Disk: read and write speed of the whole disks, free space and capacity.
  • Network: total speed, receive and send.

Startup Apps

The apps that start when you log in (XDG autostart), with a switch each. Turning one off writes an override in ~/.config/autostart; the system's own file is never changed.

Services

The system's and your own services (systemd units), with their state, filtered by the search box. Start, Stop and Restart: your own services directly, system services after the administrator password.

App Center (GNOME Software) installs, updates and removes apps from two sources:

  • Debian: the whole Debian trixie archive, tens of thousands of packages, maintained by Debian's security team.
  • Flathub: sandboxed apps, always at their latest version, many commercial apps (Spotify, Zoom, Discord, Slack…).

When an app exists in both, choose the source on its page. Updates lists system, app and firmware updates. Nothing is installed without you asking.

From a terminal

sudo apt install PACKAGE            # a Debian package
flatpak install flathub APP.ID      # a Flatpak app
pkgtui                              # search and install both in one terminal UI

Apps' Flatpak permissions (camera, files, location…) can be reviewed in Settings → App Permissions.

Dev Hub installs developer tools from their official sources, so they are always current. Installed tools show a check mark.

An install opens a window with the tool's own icon and name, a progress bar, and one line saying what is happening at this moment — Unpacking code…, Setting up… — taken from the install's own output. The terminal it comes from is behind Show Details, in case you want it; it opens by itself when something fails, which is the one time it is worth reading. When a tool needs the administrator password, it is asked for once at the start, with the terminal already open for it, instead of somewhere in the middle of a wall of text.

When a tool comes from its own apt repository, Dev Hub keeps one definition of it and one signing key, in /etc/apt/keyrings. Any other copy of the same repository — left by the vendor's own package, by an earlier attempt, or by a how-to followed by hand — is moved aside with a .aurora-disabled suffix and named in the log. Two definitions of one repository with different key paths make apt refuse every update, system updates included (Conflicting values set for option Signed-By), so installing the tool again from Dev Hub is also the way to repair a machine already in that state.

Project Workspaces

For each repository or folder, a workspace opens your editor, a terminal and Files together; in the Aurora session it can also remember where those windows were and put them back. Spotlight finds projects by name and opens their workspace from the right-click menu.

Game Hub sets up gaming in one click each. Steam, Heroic, Bottles and ProtonUp-Qt come from Flathub (sandboxed, with their own graphics runtime); GameMode, MangoHud and Lutris are Debian packages; Waydroid comes from its official repository.

Open a terminal with Super+Enter or Ctrl+Alt+T. The terminal is Ptyxis: tabs, profiles, and a menu to open shells inside distrobox, toolbox and podman containers. The font is JetBrains Mono.

The shell

  • bash by default, with Aurora's defaults in /etc/aurora/bashrc; add your own in ~/.bashrc. Dev Hub → Shells & Terminals installs zsh, fish and others and switches the default.
  • The prompt is starship: Git branch and status, language versions, command duration. Customize it in ~/.config/starship.toml (start from /etc/aurora/starship.toml).
  • Ctrl+R searches the history with fzf.
  • Aliases: ll, la, g (git), lg (lazygit), dc (docker compose), and bat, fd.

Pinned screenshots

A pinned screenshot stays above every window and on every workspace, like a sticky note of the screen: keep a reference, a code sample or a chart in view while you work in another app. Pin with Pin to Screen on a screenshot's notification or with Super+Shift+P (draw the area).

  • Drag it anywhere; the mouse wheel makes it bigger or smaller.
  • Ctrl+C copies the picture; right-click for Copy, Save As…, Open and Unpin.
  • Double-click, Esc or × unpins it.

Recording the screen

Control Center → Screen Recording starts; a red dot appears in the top bar; the same tile stops. The tile's arrow offers Record the whole screen, Record an area… (draw a rectangle) and Record the computer's sound (on or off, remembered). Super+Alt+R starts and stops from the keyboard, Super+Alt+Shift+R records an area. Recordings are MP4 files in ~/Videos/Screencasts. For more control (sound, webcam, streaming) install OBS Studio from App Center.

Clipboard history

Super+V shows what you copied lately, newest first, in Spotlight. Type to filter; Enter copies an entry again (then paste with Ctrl+V). Copied images are kept too. Pinned entries stay until you unpin them; the others are forgotten after a while.

The Clipboard window

Super+Shift+V, or Clipboard in Launchpad, opens the whole history in a window — the room with the light on, where Spotlight is the quick look.

  • Everything you copied, newest first, with pinned entries at the top and the pictures among them. Each entry says how long ago it arrived and how many lines it has; code and paths are shown in a monospace font.
  • Search at the top; Enter takes the first match.
  • Click an entry to copy it — the window closes and you paste with Ctrl+V. The text is handed to the system clipboard properly, so it survives the window closing.
  • The pin keeps an entry at the top for good; the bin removes one (Delete on the selected entry does the same). The menu empties the whole history, after asking.
  • It follows the history as you copy: leave it open and new entries appear.
  • Esc closes it, Ctrl+F returns to the search field.

Settings → Privacy & Security → Clipboard History turns the history off (Remember copied text), clears it, and Open Clipboard… opens this window. The history stays on this computer; passwords copied from password managers are never recorded. The Clipboard widget shows the latest entries on the desktop.

USB Stick Writer (Launchpad, or right-click an image in Files → Open With) puts a disk image on a USB stick — an Aurora ISO to install from, or any other system's.

  1. Choose the image: an .iso or .img. Compressed downloads work as they are (.gz, .xz, .bz2, .zst, and a .zip holding a single image): they are unpacked while they are written, so there is no need to unpack a five-gigabyte download first.
  2. Choose the stick. Only removable and USB disks are listed, and the disk this system is running from is never among them — nor, on a live session, the stick you booted from. A disk that is mounted says where, and is unmounted for you.
  3. Erase and Write. The dialog names the stick, its size and the image; everything on the stick is replaced.

Checking the download first

Check the download compares the file with its SHA-256 — the long line of letters and numbers a download page gives you. If the download came with one beside it (aurora-os-0.1-amd64.iso.sha256, or a SHA256SUMS naming it), it is filled in for you; otherwise paste it from the page. Check reads the file through and says whether it matches. Worth doing before writing: a half-finished download makes an installer that fails in the middle, and the check is the only way to tell one from a good one by looking.

Options

Check the stick afterwards
On by default. Reads the stick back when the write is done and compares it with the image, byte for byte. Worth the extra minute: a stick that quietly drops writes is the usual reason a freshly made installer won't boot, and a counterfeit stick that claims more space than it has is caught here rather than halfway through an installation.
Eject when finished
On by default. Flushes the stick and powers it down, so it can be pulled out as soon as the window says so.

Both are remembered for next time.

Giving a stick its life back

A stick that has carried an installer is no use for files: it holds a read-only image, and Windows offers to format it. The menu's Erase the Stick… makes it one empty disk again, with a name you choose and a format: exFAT (the default — Windows and macOS read it too, and it holds files larger than 4 GB), FAT32 (what the oldest things read) or Ext4 (Linux only, with permissions).

Writing asks for your password, because overwriting a disk needs it. The checks above are made again by the part that runs with those privileges (/usr/libexec/aurora-usb-write), so a mistake or a misbehaving program cannot talk it into writing over the system's own disk.

Torrents (Transmission)

Transmission, the BitTorrent client, is installed but never starts by itself: open it from Launchpad when you need it. It is also set up to stay quiet until you use it: the public peer network (DHT), local peer discovery (LPD), peer exchange (PEX) and opening a port on your router (UPnP/NAT-PMP) are off, and added torrents don't start until you press Start. With these off, opening Transmission contacts nobody.

Many company networks flag any BitTorrent traffic, including the single contact a client makes when it joins the DHT. If you use torrents at home and want magnet links to find peers, turn the switches on in Transmission → Preferences → Network (and Privacy). They are kept in ~/.config/transmission/settings.json; new accounts start from /etc/skel/.config/transmission/settings.json.
