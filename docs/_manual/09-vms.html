Aurora runs well in a virtual machine. Give it 4 GB of memory (8 GB for AI models), 2 or more processors and a 40 GB disk. Guest tools for QEMU/KVM (agent, SPICE), VirtualBox, VMware and Hyper-V are included.

Graphics in a VM

With 3D acceleration (virtio-gpu with virgl, VirtualBox or VMware with 3D on) the Aurora session uses it. Without it, Wayfire draws on the processor, or Aurora uses the Compatibility session where Wayfire can't run (see Desktop sessions).

GNOME Boxes and virt-manager

Open the ISO, choose Debian 13 as the operating system, 4 GB of memory and 2 or more processors. virt-manager: enable UEFI (OVMF) if you want it.

QEMU from a terminal

sudo apt install qemu-system-x86 qemu-utils ovmf     # Debian/Ubuntu
qemu-img create -f qcow2 aurora.qcow2 40G
qemu-system-x86_64 -enable-kvm -machine q35 -cpu host -smp 4 -m 4G \
  -cdrom aurora-os-VERSION-amd64.iso -boot d \
  -drive file=aurora.qcow2,if=virtio \
  -device virtio-vga-gl -display gtk,gl=on \
  -device intel-hda -device hda-duplex \
  -nic user,model=virtio-net-pci -usb -device usb-tablet
  • -device virtio-vga-gl -display gtk,gl=on gives the VM 3D acceleration. Without it (for example over SSH) use -vga std -display gtk.
  • Add -drive if=pflash,format=raw,readonly=on,file=/usr/share/OVMF/OVMF_CODE_4M.fd to boot with UEFI; keep the same firmware for later boots.
  • After installing, start again without -cdrom and -boot d.

From Aurora's source tree, build/run-qemu.sh does this with options (--uefi, --disk FILE, --software, --spice PORT, --vnc N).

On a server, watched from another computer

# on the server
build/run-qemu.sh --uefi --disk aurora.qcow2 --spice 5930 aurora-os-VERSION-amd64.iso
# on your computer
ssh -L 5930:127.0.0.1:5930 user@server
remote-viewer spice://127.0.0.1:5930

Windows with WSL 2

WSL 2 supports nested virtualization, so the QEMU commands work in Ubuntu on WSL: check that /dev/kvm exists, install QEMU, add yourself to the kvm group (sudo usermod -aG kvm $USER, then wsl --shutdown), and start with --software.

VirtualBox and VMware

Create a Debian 64-bit VM, enable EFI for UEFI, give it 128 MB of video memory and turn 3D acceleration on if available. The guest tools are already in Aurora.

Hyper-V is in Windows 10 and 11 Pro, Enterprise and Education. Hyper-V never gives a Linux VM your graphics card for its screen: the desktop is drawn by Hyper-V's virtual display, in software. Your GPU can still run Aurora AI models, from Windows.

Turn on Hyper-V (once)

Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V -All

In PowerShell as administrator, then restart Windows.

Create the VM with the script

tools/hyperv/New-AuroraVM.ps1 from Aurora's repository creates everything from the ISO's path. In PowerShell as administrator:

powershell -ExecutionPolicy Bypass -File .\New-AuroraVM.ps1 -IsoPath "$env:USERPROFILE\Desktop\aurora-os-VERSION-amd64.iso"

It creates “Aurora” (Generation 2, 8 GB, 4 processors, 60 GB disk in C:\VMs), turns Secure Boot off, sets the boot order (DVD, disk, network), keeps Windows' standard and automatic checkpoints, sets the resolution and enhanced session, starts the VM and opens its window. Run it again with a newer ISO: it keeps the VM and its disk and only swaps the ISO. Options: -Name, -MemoryGB, -Processors, -DiskGB, -Folder, -Switch, -Width, -Height, -NoStart, -Recreate.

Install

Install as on a PC (Installing Aurora OS). After the restart the VM starts from its disk; remove the ISO from the DVD drive in the VM's settings when you no longer need it.

If the installed system doesn't start

It shows “Start PXE over IPv4”
The network is before the disk in the boot order: 
Set-VMFirmware -VMName Aurora -BootOrder (Get-VMDvdDrive -VMName Aurora), (Get-VMHardDiskDrive -VMName Aurora), (Get-VMNetworkAdapter -VMName Aurora)
The firmware can't read the disk
On some hosts the VM's firmware reads the virtual disk only through a checkpoint. Keep checkpoints on: 
Set-VM -Name Aurora -CheckpointType Standard -AutomaticCheckpointsEnabled $true
A report for help
tools/hyperv/Get-AuroraBootReport.ps1 -Name Aurora collects the VM's settings, Hyper-V's log and the boot files (read-only) into a folder on the Desktop.

Use your GPU for Aurora AI

Run Ollama or LM Studio on Windows (they use your GPU), allow connections from the network, and in Aurora choose Settings → AI → Provider → OpenAI-compatible API with Windows' address (for Ollama, http://WINDOWS-IP:11434/v1). The full guide, including experimental GPU partitioning, is HYPERV.md in Aurora's repository.
