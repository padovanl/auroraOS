# Desktop and installation audit — 11 October 2026

The review covered README.md, HYPERV.md, all twelve manual source chapters,
the website source pages, generated settings/reference tables, the desktop
implementation and the available test suites. The aim was to make wallpaper
selection understandable, provide reliable application startup feedback and
animate context menus, then check the surrounding desktop and installation paths.

## Changes

- Wallpaper settings show six distinct choices with explanations and inline,
  searchable thumbnail galleries. Static pictures do not expose misleading
  movement controls. Personal still images and videos can be imported. Thumbnail
  work is bounded and rapid changes are coalesced to keep GTK responsive.
- Clicking a focused application's top-bar window button minimizes it; clicking
  its minimized button restores it. This was committed with the wallpaper-settings and topbar fixes.
- All application launches in the shell share startup feedback, including search
  results and desktop files/folders. A progress cursor is set before GIO launches
  the application, and a brief message confirms the request. Repeated pending
  launches are deduplicated; separate documents and explicit desktop actions are
  preserved. Cursors are restored after a matching window appears, launch failure,
  or a 15-second timeout. Error messages also expire.
- Aurora's GTK context menus use 150 ms opening and 110 ms closing transitions.
  Reopening during closure cancels the pending dismissal. For native outside-click
  dismissal, an inert last-frame picture completes the fade after the real input
  grab has been released. GTK's animation preference and Aurora's Window animations
  switch both disable the transitions.
- Privileged switches in Privacy and Sharing no longer block GTK while pkexec
  waits for authorization. Cancellation restores the old switch state without
  submitting another request, and repeated requests are blocked while pending.
- SSH activation adds Aurora's own firewall application rule. Deactivation stops
  both service and socket and removes that rule; a failed start rolls back the
  rule. Independently configured OpenSSH rules are preserved.
- Privacy's Lock now control is actionable.
- Checked Settings commands report missing executables and timeouts rather than
  returning an empty success-like result.
- Displays supports X/Y placement, including negative coordinates, with the same
  keep/revert/countdown and persistence as other display changes. The manual now
  describes the implemented controls instead of promising a nonexistent primary
  monitor selector.
- Window previews crop partially offscreen windows to visible monitor bounds and
  preserve negative coordinates for monitors left of the primary display.
- Local AI process tracking validates reserved/damaged/stale PID files and process
  command lines before treating a process as Aurora's server or sending SIGTERM.
- Shell commands sent by compositor shortcuts use a small GIO sender instead of
  importing GTK and re-executing the rendering process. The full shell is loaded
  only for startup. Launcher entries with the same complete launch command can match the same
  window; the installer also declares its native startup WM class explicitly.
- The emoji shortcut now opens 24 useful choices immediately. Previously its
  empty `:` query fell through to a web search instead of the emoji provider.
- Documentation removes obsolete package/ISO size estimates and distinguishes
  downloaded wallpaper attribution from Aurora's original generated artwork.
- SSH generates host keys before running its configuration check, rather than
  appending key generation after a check that fails on a fresh image.
- Image overlay and desktop-library installation normalize permissions from Windows
  checkouts: directories 0755, data/configuration 0644, scripts 0755, sudoers 0440.
  Existing private files outside the overlay keep their permissions.

## Test corrections

The image check now expects Calamares to leave EFI fallback ownership to Aurora's
EFI helper, which protects the existing Windows path. QEMU monitor commands wait
for completion instead of guessing when slow screenshot writes have finished.
The dock comparison follows the actual screenshot size; launcher dismissal uses
Esc rather than switching modes. General UI comparisons freeze the animated
wallpaper; playback tests explicitly enable it. Files location-bar comparisons
measure the actual header. GTK interaction tests drain close/unmap events before
exiting. Smoke testing enumerates every registered Settings page and treats
nonzero exits and timeouts as failures.

`make test-system-native` runs GTK units, menus, administrative switches,
two-display changes, Files and Assistant. `make test-startup-menus` exercises a
deliberately slow app through real desktop clicks, repeated launches and dismissal
of context menus in an isolated live VM.

The existing ISO still has the old SSH drop-in ordering and checkout-derived
permissions. The new image permission gate rejects that payload; overlay staging
and native installed-library permissions are checked separately. These corrections
require rebuilding the ISO, just as the desktop changes do.

## Limits

This is evidence for the paths tested, not a guarantee that no bugs exist.
The earlier Hyper-V freeze was not diagnosed because that investigation was
cancelled; QEMU and headless results do not explain its cause. Physical GPU and
multi-monitor combinations, suspend/resume, Bluetooth peripherals, printers,
fingerprint readers, and real hardware firmware require device testing. The
review did not install every optional Dev Hub recipe, download every AI model,
or contact external mail/cloud accounts. Those paths retain their existing
unit/configuration coverage rather than a claim of hardware or service validation.
