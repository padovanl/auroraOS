# Cross-component bug audit — 12 October 2026

This pass continues beyond Files and Settings. Inspection covered shell service
lifecycles and recording, notification/history handling, clipboard storage,
Windows migration, USB download checking, storage housekeeping and file tools.
The fixes below address reproduced failures, rather than adding speculative
features. Usage changes are documented in the corresponding manual chapters.

## Reproduced problems and fixes

| Component | Trigger and previous behavior | Result |
| --- | --- | --- |
| Screen recording | Stopping a recorder waited up to ten seconds on the shell thread; repeated requests and spontaneous process exits were not handled consistently. | SIGINT is sent once, waiting/killing/reaping happens in a worker, the tile shows Saving recording…, and another recording waits for finalization. A process-exit watcher updates the UI and publishes the saved path. An unwritable Videos folder no longer raises through the shell. |
| Notifications | Do Not Disturb and muted apps dropped active IDs and timers, so replacing a progress notification duplicated history. Closing an already expired notification emitted a second closing signal. | Hidden notifications retain their ID and lifecycle; replacements update one history entry, transient updates refresh history, and closing signals are emitted once. Unknown CloseNotification requests return a D-Bus error. Critical popups still bypass Do Not Disturb. |
| Clipboard history | A pinned entry fell off after 100 later copies; rejected blank/oversized copies still accumulated metadata; pin/delete could race the watcher. | Pinned entries take priority within the 100-entry limit. Metadata is bounded by retained entries, invalid copies are ignored, and text-history writers share the same lock. |
| Windows migration | Exporting bookmarks/background overwrote previous exports. A dangling destination link was treated as an unused filename and copying followed it. | Exports choose unused numbered names; bookmarks use exclusive creation and GIO copying preserves occupied destinations, including links and names created after the initial check. |
| USB Stick Writer | Looking for disk.img in SHA256SUMS also matched disk.img.old and could pick its checksum. A named sidecar also accepted the first hash regardless of its named image. | GNU text/binary and BSD tagged records match the complete filename; a bare digest remains supported in a dedicated sidecar. |
| Image resizing | Converting an original from JPEG to PNG could overwrite an unrelated PNG and delete the JPEG. An encoding failure could truncate the original; copying could follow a dangling output link. | Encoding happens in a temporary file. Other existing names are preserved, output-name selection includes links, failed encoding removes temporary output, and an original edited during encoding is not replaced. |
| Batch rename | Replacing text with ../outside/ moved files outside their selected folder. The rename syscall could replace a destination created after validation. | Every resulting name is checked before any rename; paths, empty names and . or .. are rejected. GIO moves preserve occupied destinations and successful renames retain Undo/Redo. |

## Verification

Nine initial unit scenarios failed against the preceding sources, covering images,
USB checksums, clipboard limits and Windows migration. Two further failures were
reproduced separately: a real GTK batch-rename dialog moved the temporary fixture
outside its folder, and a controlled recorder process showed its wait running on
the shell thread. Two notification regressions then reproduced duplicate history
and repeated closing signals. Logs retain these thirteen failures alongside the
corrected runs.

Notification identity, replacement and invalid-ID behavior follow the
[freedesktop notification protocol](https://specifications.freedesktop.org/notification/latest/protocol.html).

The new regression checks exercise image-save failure and concurrent edits,
clipboard pin/watcher interleaving, whole-filename checksums, export collisions,
destination links, responsive recorder shutdown, stubborn-process reaping,
spontaneous exit, failed startup and restarting after a stale process. The GTK
batch test also verifies ordinary rename and Undo/Redo. Notification regressions
check hidden replacements and expiration, muted apps, critical bypass, transient
history removal, persistent timeouts and the unknown-ID D-Bus reply.

`make test-system-native` includes the new dialog check alongside the existing
menu, display, clipboard, file and Assistant scenarios. Unit regressions live in
`tests/unit/test_daily_data_preservation.py`, `tests/unit/test_services.py` and
`tests/unit/test_notification_lifecycle.py`.
Artifacts are in `work/audit-bugs-2026-10-11/`; the directory retains the date on
which this pass began.

Final native Wayland run: **453 unit tests passed, one skipped**, followed by
successful menu, settings/system, daily interaction, batch-rename, file-operation
and Assistant scenarios (`native-notifications/scenario-result`: 0). No Python
tracebacks or GTK critical errors were reported. Static checks passed, including
syntax, shellcheck, schemas, catalog generation, wallpaper size limits and the
74-page generated manual (`static-notifications.log`).

The complete shell/app smoke run also passed (`smoke-notifications/scenario-result`
and `smoke-notifications/smoke/result`: 0): every Aurora app and all 27 Settings
pages opened, plus Spotlight, Launchpad, code/PDF/image Quick Look, overview,
clipboard history, Assistant streaming/local attachments and widget popovers.
No Python tracebacks or GTK critical errors were reported in the resulting logs.

An initial standalone run used a read-only container with a non-executable /tmp.
It passed the new scenarios but prevented existing fixture scripts and preference
writes from running. Those infrastructure failures are not counted as desktop
bugs; the standard isolated Wayland runner supplies the intended environment.

## Limits

Recorder regression processes are controlled test doubles; this verifies event-loop
responsiveness and process lifecycle, not hardware-specific encoding. No USB stick
or Windows disk was written during this audit. USB tests validate selection and
checksum parsing; migration tests use temporary Windows-profile fixtures. The ISO
currently on disk predates these changes and needs rebuilding before image-level
release checks can validate their inclusion.
